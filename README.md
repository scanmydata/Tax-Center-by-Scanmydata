# ScanMyData Tax Center

Android εφαρμογή για λογιστικά γραφεία: μαζική διαχείριση κωδικών πελατών,
αυτόματη λήψη φορολογικών εντύπων από ΑΑΔΕ/ΕΦΚΑ, και αποστολή τους στους πελάτες
με email.

> **Χειρίζεται πολύ ευαίσθητα δεδομένα** — κωδικούς TAXISnet, κλειδάριθμους,
> εισοδήματα και οφειλές. Δες [Ασφάλεια και GDPR](#ασφάλεια-και-gdpr).

---

## Τι κάνει

* **Εισαγωγή πελατών** — μαζικά από το `Κωδικοί Υπόχρεων.xlsx` του λογιστικού
  προγράμματος (Epsilon Hyper/Extra, TaxSystem), ή χειροκίνητα. Πάντα με
  προεπισκόπηση πριν γραφτεί οτιδήποτε.
* **Άντληση στοιχείων από το TAXIS** — με τους κωδικούς του πελάτη γεμίζουν
  ονοματεπώνυμο, ΑΦΜ, ΔΟΥ και είδος υπόχρεου από το Μητρώο ΑΑΔΕ, και ο ΑΜΚΑ από
  το MyAMKA. Λειτουργεί και σε πελάτη που δεν έχει αποθηκευτεί ακόμη.
* **Email πελατών** — συμπληρώνονται αυτόματα από το **Μητρώο Επικοινωνίας
  ΑΑΔΕ**, γιατί το export δεν τα περιέχει. Ο λογιστής μπορεί να προσθέσει και
  δεύτερη διεύθυνση.
* **Τίποτα δεν γράφεται χωρίς έγκριση** — κάθε άντληση αφήνει *προτάσεις*
  «πριν → μετά» ανά πεδίο, με διακόπτη στην καθεμία. Μια μαζική άντληση σε 40
  πελάτες δεν σβήνει σιωπηλά μια χειροκίνητη διόρθωση.
* **Λήψη εντύπων** — Ε1, Ε2, Ε3, Εκκαθαριστικό, ΦΕΝΠ/Ν, Φ2/Φ4/Φ5, ΦΜΥ και λοιποί
  παρακρατούμενοι, ΕΝΦΙΑ, Ε9/Περιουσιακή, Μισθωτήρια, Ταυτότητα Οφειλής,
  Φορολογικός Λογαριασμός, Τέλη Κυκλοφορίας, Στοιχεία Μητρώου, Ειδοποιητήρια και
  Βεβαιώσεις ΕΦΚΑ/ΤΕΚΑ, ΠΒΟ ΚΕΑΟ, Καρτέλα Εργοδότη, ΑΤΛΑΣ, ΑΜΚΑ.
* **Αποστολή** — με Gmail API, μεμονωμένα ή μαζικά, ένα email ανά πελάτη. Η
  μαζική αποστολή περνά από οθόνη που δείχνει **ονομαστικά** κάθε παραλήπτη.
  Στην ίδια οθόνη με τη λήψη υπάρχει και η **αποστολή των κωδικών στους ίδιους
  τους πελάτες** — με το συνθηματικό και τον κλειδάριθμο **κλειστά εξ ορισμού**.
* **Ημερολόγιο αποστολών** — μήνας ή εβδομάδα, με τις αποτυχίες σε κόκκινο και
  επανάληψη με ένα πάτημα.
* **Καρτέλα οφειλών** — τι χρωστά ο πελάτης τώρα, χωριστά σε ΑΑΔΕ και ΚΕΑΟ (και
  στο ΚΕΑΟ ανά φορέα): υπόλοιπο, δόση που τρέχει, ταυτότητα πληρωμής. Ενημέρωση
  με ένα πάτημα ή προγραμματισμένα, και μήνυμα οφειλής με SMS ή Viber.
* **Αιτήματα προς την ΑΑΔΕ** — «Τα Αιτήματά μου» κάθε πελάτη, με καθημερινό
  έλεγχο και ειδοποίηση όταν απαντηθεί κάτι. Κάθε αίτημα ανοίγει ολόκληρο, με τα
  συνημμένα που υποβλήθηκαν και τα έγγραφα της απάντησης.
* **Αντίγραφο ασφαλείας** στο Drive, κρυπτογραφημένο πριν ανέβει με passphrase
  που ξέρει μόνο ο χρήστης.

## Πώς τρέχουν οι διαδικασίες

Οι διαδικασίες λήψης είναι **αυτούσια** τα configs του
[`recerse-engineer/runner`](https://github.com/scanmydata/Taxsystem-reverse-engineer-fix) —
όχι μεταφρασμένα σε Kotlin. Ένα λεπτό shim layer (`assets/engine/shims.js`) δίνει
στο WebView ό,τι περιμένουν από το Node: `fs`, `path`, `fetch`, `Buffer`,
CommonJS `require`.

```
configs/*.js  +  hyper-http.js      ← byte-για-byte από τον runner
        │
   shims.js  ── __bridge ──►  OkHttp (HTTP)  ·  FileBridge (αρχεία)
        │
   browser-step.js ──────────►  WebView   ← μόνο για ΕΝΦΙΑ (ADF + F5)
```

**Γιατί έτσι:** ένα source of truth με τον desktop runner. Νέο έντυπο σημαίνει
ένα `.js` αρχείο, όχι διπλή υλοποίηση που θα αποκλίνει με την πρώτη αλλαγή.

Συγχρονισμός με τον runner:

```bash
npm run vendor          # αντιγραφή engine + configs
npm run vendor:check    # exit 1 αν έχουν αποκλίνει
npm test                # τρέχει τον engine σε sandbox χωρίς Node builtins
```

Το `npm test` στήνει `vm` context **χωρίς κανένα Node builtin** και τρέχει εκεί
τον αυτούσιο engine — cookie jar, χειροκίνητα redirects, το υποχρεωτικό
`charset=UTF-8` (χωρίς αυτό ο JSF του e-ΕΦΚΑ γυρίζει τα ελληνικά ως `?`), και τον
έλεγχο `%PDF` από magic bytes. Τρέχει και στο CI **πριν** χτιστεί το APK.

## Ασφάλεια και GDPR

Ο λογιστής είναι **εκτελών την επεξεργασία** για λογαριασμό των πελατών του. Η
εφαρμογή του δίνει τα εργαλεία να το αποδείξει.

| Απαίτηση | Υλοποίηση |
|---|---|
| Ελαχιστοποίηση (άρθρο 5) | Από τις 83 στήλες του export κρατάμε 14. Οι υπόλοιπες δεν φτάνουν καν στη βάση. |
| Ασφάλεια (άρθρο 32) | SQLCipher για όλη τη βάση **και** AES-256-GCM ανά τιμή, με κλειδί στο Android Keystore που δεν εξάγεται. |
| Privacy by design (άρθρο 25) | Διαγνωστικά κλειστά εξ ορισμού· `allowBackup=false`· καμία τηλεμετρία· κλείδωμα με βιομετρικά και `FLAG_SECURE` σε όλη την εφαρμογή. |
| Αρχείο δραστηριοτήτων (άρθρο 30) | `audit_log`: τι έγινε, πότε, σε ποιον πελάτη. Ποτέ τιμές. Εξάγεται σε CSV. |
| Διαγραφή (άρθρο 17) | Διαγραφή πελάτη = κωδικοί + έγγραφα + εγγραφές, σε ένα βήμα. |
| Φορητότητα (άρθρο 20) | Εξαγωγή όλων των δεδομένων ενός πελάτη σε ZIP — χωρίς τους κωδικούς του, εσκεμμένα. |
| Περιορισμός αποθήκευσης (άρθρο 5) | Αυτόματη διαγραφή ληφθέντων PDF μετά από N μήνες (24 εξ ορισμού). |

Επιπλέον:

* Κανένας κωδικός δεν φτάνει σε log — ο `Redactor` κόβει κωδικούς,
  κλειδάριθμους, κλειδιά API, tokens και ΑΜΚΑ. Το ΑΦΜ μένει σκόπιμα, αλλιώς τα
  διαγνωστικά είναι άχρηστα.
* **Δεν παρακάμπτεται 2FA, OTP ή CAPTCHA.** Όπου το TAXISnet τα ζητά, η σελίδα
  εμφανίζεται στον χρήστη και τα συμπληρώνει ο ίδιος.
* Μετά την εισαγωγή, η εφαρμογή προτρέπει να **διαγραφεί το XLSX** από τη
  συσκευή: είναι το μόνο σημείο της ροής όπου κωδικοί υπάρχουν σε καθαρό κείμενο.

## Build

Δεν χρειάζεται Android Studio — το build γίνεται στο GitHub Actions. Κάθε push
στο `main` παράγει APK + AAB και δημοσιεύει
[release](https://github.com/scanmydata/Tax-Center-by-Scanmydata/releases). Στο
ίδιο release προστίθεται και το `.ipa` του iOS — βλ. [iOS](#ios).

Τοπικά:

```bash
gradle assembleRelease -PappVersionCode=1 -PappVersionName=0.1.0
```

Τα release builds υπογράφονται με το keystore του γραφείου (τα GitHub Secrets
είναι στη θέση τους). Δες
[docs/google-cloud.md](docs/google-cloud.md) για keystore, GitHub Secrets και
στήσιμο του OAuth client.

## iOS

Ο φάκελος [`ios/`](ios/) είναι η εφαρμογή για iPhone και iPad. Χτίζεται στο ίδιο
workflow: κάθε push στο `main` παράγει και ένα `.ipa`, που ανεβαίνει στο ίδιο
release λίγα λεπτά μετά το APK.

**Δεν είναι η ίδια εφαρμογή μεταγλωττισμένη αλλιώς.** Ο κώδικας του Android
είναι Kotlin και δεν τρέχει σε iPhone. Αυτό που μοιράζονται οι δύο είναι το
δυσκολότερο κομμάτι: ο JS engine που μιλά με τις πύλες
(`app/src/main/assets/engine`) μπαίνει **αυτούσιος** στο bundle του iOS και
τρέχει μέσα σε κρυφό `WKWebView`, όπως στο Android μέσα σε κρυφό `WebView`. Το
περίβλημα — πελάτες, λήψη, έγγραφα — είναι γραμμένο από την αρχή σε SwiftUI.

Τι έχει η πρώτη έκδοση:

- πελάτες (καταχώρηση, διόρθωση, διαγραφή), με τους κωδικούς στο **Keychain**
- λήψη εντύπων από ΑΑΔΕ και e-ΕΦΚΑ, με τον ίδιο κατάλογο και τα ίδια μηνύματα
  («βρέθηκε / δεν βρέθηκε / δεν έγινε σύνδεση / κάτι χάλασε»)
- έγγραφα ανά πελάτη: άνοιγμα, αποστολή από το φύλλο κοινοποίησης του iOS
  (Mail, Viber, …), διαγραφή
- κλείδωμα με Face ID / Touch ID / κωδικό συσκευής

Τι **δεν** έχει ακόμη: εισαγωγή από Excel, αποστολή με Gmail και ημερολόγιο
αποστολών, καρτέλα οφειλών και έντυπα ΚΕΑΟ, αιτήματα ΑΑΔΕ, αυτόματες
ενημερώσεις, αντίγραφο στο Drive. Κάθε ένα είναι δουλειά μεταφοράς από Kotlin
σε Swift, όχι ρύθμιση του build.

**Εγκατάσταση.** Το `.ipa` είναι ανυπόγραφο. Η Apple δεν επιτρέπει εγκατάσταση
σε iPhone χωρίς υπογραφή — δεν υπάρχει αντίστοιχο του «άγνωστες πηγές» του
Android. Για να μπει σε συσκευή χρειάζεται λογαριασμός
[Apple Developer](https://developer.apple.com/programs/) (99 $/έτος). Με αυτόν,
το workflow μπορεί να υπογράφει το build και να το στέλνει στο TestFlight — το
βήμα αυτό δεν έχει στηθεί ακόμη, γιατί θέλει το πιστοποιητικό του λογαριασμού.

Το Xcode project δεν είναι στο git: παράγεται από το
[`ios/project.yml`](ios/project.yml) με το [XcodeGen](https://github.com/yonaskolb/XcodeGen).
Σε Mac:

```bash
cd ios && xcodegen generate && open TaxCenter.xcodeproj
```

Τα τεστ τρέχουν στο CI σε προσομοιωτή iPhone και φορτώνουν τον πραγματικό
engine: ένα ολόκληρο config του runner εκτελείται από τη σύνδεση ώς το αρχείο,
απέναντι σε ψεύτικη πύλη.

## Εικονίδια

```powershell
powershell -ExecutionPolicy Bypass -File tools/make-icons.ps1 -Source "διαδρομή\λογότυπο.png"
```

Κόβει το πάνω-αριστερά τεταρτημόριο του λογότυπου, βρίσκει το bounding box του
σχήματος και παράγει adaptive icon σε όλα τα densities, συν λογότυπο 120px για
την οθόνη συγκατάθεσης της Google.
